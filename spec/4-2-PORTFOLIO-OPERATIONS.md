# 4-2. 포트폴리오 운영

메인 한 페이지에 들어가는 **이력과 프로젝트**를 다룬다. 무엇을 싣고 무엇을 뺄지, 어느 값을 정본으로 삼을지, 프로젝트 문서를 어떻게 쓸지를 정한다. 블로그 글은 [4-1](4-1-BLOG-OPERATIONS.md)에 있다.

블로그와 나눈 이유는 **되돌리기 비용이 다르기** 때문이다. 글은 언제든 고치고 지울 수 있지만, 이력은 사람을 판단하는 자료라 한 번 실은 것을 빼기 어렵고 틀린 값은 신뢰를 깎는다.

```text
§4-2-1   이력 데이터의 정본     값이 어긋날 때 무엇을 따르는가
§4-2-2   싣는 것과 빼는 것      항목 단위 판단과 근거
§4-2-3   프로젝트 선정          Projects 에 무엇을 넣는가
§4-2-4   프로젝트 문서 작성     파일 구조와 본문 규칙
§4-2-5   마에스트로 성과물 표기  의무 사항
```

## 4-2-1 이력 데이터의 정본

| 항목 | 정본 |
| --- | --- |
| 학력·활동·수상·자격 | **GitHub 프로필 README** |
| Tech Stacks | 노션 개인 소개 페이지 ▶ Tech Stacks |
| 프로젝트 | 각 저장소의 README·PR과 `src/content/projects/*.md` |

값이 어긋나면 GitHub README를 따른다. 실제로 GPA가 두 곳에서 달랐고 GitHub 쪽이 최신이었다([3-2](3-2-DESIGN-DECISIONS.md) §3-2-8 6번). `MUST`

날짜는 국립국어원 점 표기(`2026. 9.`)를 쓰고 월에 0을 채우지 않는다. 0을 채우는 것은 ISO 8601(`2026-09`)의 규칙이며 두 체계를 섞지 않는다. `MUST`

## 4-2-2 싣는 것과 빼는 것

무엇을 싣느냐는 디자인만큼 되돌리기 어렵다. 뺀 것도 이유와 함께 남긴다.

| 항목 | 판단 | 근거 |
| --- | --- | --- |
| TOEIC 755 (2025. 8.) | **싣지 않음** | 자격 섹션의 다른 항목(TOPCIT·SQLD·정보처리기능사)과 축이 다르고, 755는 개발 직군에서 판단을 바꾸지 않는다. 어학 점수가 필요한 자리는 공채 지원서의 어학 칸이지 포트폴리오가 아니다. **850 이상이면 재검토** |
| solved.ac | 히어로에서 **제거** | 사용자 요청. 연락 수단 위주로 좁혔다 |
| 이메일 | **공개** (`kyunghyun.dev@gmail.com`) | 사용자가 명시적으로 지정. 임의로 올리지 않았다 |
| 이전 블로그 | 히어로에서 빼고 **푸터에 유지** | 348편이 꾸준함의 근거라 지우기 아깝고, 히어로는 연락 수단만 남긴다 |
| 수상·자격 상세 | **한 줄 안에 연하게** | 두 줄로 내리는 안을 시도했다가 되돌렸다. Activity 와 리듬이 어긋나 목록 전체가 산만해졌다 |
| 수상 항목의 외부 링크 | **보류** | 공지사항·회고로 링크를 잇는 안이 있으나 걸 대상이 아직 없다. 회고가 나오면 그때 잇는다 |

**다른 사람의 정보는 싣지 않는다.** 팀원·멘토의 실명, 개인이 만든 포트폴리오 URL, 공개되지 않은 심사 자료의 내용은 참고만 하고 사이트에 옮기지 않는다. `MUST`

## 4-2-3 프로젝트 선정

Projects 는 **결과를 말할 수 있는 것만** 싣는다. 현재 5개다 — 마냑·이름잇기·LinKHU·WAVI·BOJ Performance. 운영 중 3개, 운영 중단 1개, 실측 사용자 2개로 어느 것을 눌러도 빈 페이지가 나오지 않고, 그것이 목록 전체의 신뢰를 만든다.

추가 제안이 오면 세 가지를 먼저 확인한다. **하나라도 아니면 넣지 않는다.** `SHOULD`

1. 사용자가 그것을 내보이고 싶어하는가
2. 결과를 말할 수 있는가
3. 트러블슈팅이나 판단을 쓸 재료가 있는가

1번이 가장 크다. **포트폴리오는 "이것에 대해 물어봐 달라"고 초대하는 문서**라서, 본인이 마음에 안 드는 항목을 올리면 면접에서 정확히 그 얘기를 하게 되고 방어적으로 답하게 된다. 자신 없는 항목은 없느니만 못하다.

넣지 않기로 한 것 (2026-08-02 판단)

| 프로젝트 | 뺀 이유 |
| --- | --- |
| KHUromise (2022) | **이미 Awards 에 있어 중복이다.** 배포되지 않은 4년 전 학습 프로젝트가 결과 뚜렷한 5개 옆에 놓이면 목록 평균을 내린다. 대신 Awards 항목에 프로젝트명과 저장소 링크를 붙였다 |
| 리버스튜터링 (2026. 4.) | 쓸 재료가 없다. README 도 결과도 없으면 페이지에 "만들었다"밖에 못 쓴다 (3번 불충족) |
| AM8 (2025. 11. ~ 12.) | 사용자가 결과를 모른다고 했다(2번 불충족). Activity 의 `GDG on Campus` 로 이미 표현돼 있어 별도 카드로 얻는 것이 없다. **운영 수치를 말할 수 있게 되면 재검토** |

뺀 프로젝트도 **블로그 소재로는 살아 있다.** 포트폴리오 카드에 안 맞는 것과 쓸 가치가 없는 것은 다르다 — KHUromise 는 카드 한 장으로 안 나오는 4년치 성장을 회고 글로는 드러낼 수 있다.

## 4-2-4 프로젝트 문서 작성

`src/content/projects/<슬러그>.md` 하나가 프로젝트 하나이며, 메인 카드와 상세 페이지가 그 파일을 함께 읽는다. 스키마는 [3-1](3-1-DESIGN-ARCHITECTURE.md) §3-1-3.

본문 소제목은 다음 순서를 기본으로 한다. 필요 없는 것은 지우면 그 섹션이 사라진다.

```text
## 작업 배경 및 해결 과정   무엇이 막혔고 왜 이 방법을 골랐는지. 산문
## 구현 내용                 한 일을 항목으로
## 결과                      가능하면 수치로
```

AS-IS → TO-BE는 본문이 아니라 프런트매터의 `asIs` / `toBe` 배열에 적는다. 기술 스택도 본문이 아니라 `stack` 배열이다.

이미지는 `public/images/<슬러그>/`에 두고 본문에서 `/images/<슬러그>/<파일>`로 참조한다. 외부 호스트를 링크하지 않는다([2](2-REQUIREMENTS.md) §2-3). 원본이 크면 `sips -Z 1200 -s format jpeg`로 줄여 넣는다 — 화면 폭이 54rem이라 1200px을 넘길 이유가 없다. `SHOULD`

트러블슈팅은 **기억이 아니라 이슈·PR에서 끌어온다.** 저장소에 남은 PR 본문에 원인·판단·검증이 이미 적혀 있으므로, 지어내지 말고 그것을 근거로 쓴다. `SHOULD`

**결과는 수치로 쓴다.** "개선했다"가 아니라 "1.48GB → 268MB"처럼 쓴다. 수치가 없으면 그 항목은 읽는 사람에게 아무것도 주지 않는다. `SHOULD`

**출시되지 않은 것을 출시된 것처럼 쓰지 않는다.** 구현하지 못한 기능은 `stack`에서도 빼고 본문에서도 미완으로 적는다. `MUST` 지금 상태를 말할 때는 현재형을 쓴다 — 계속 사실인 것을 과거형으로 쓰면 끝난 일처럼 읽힌다.

## 4-2-5 마에스트로 성과물 표기 (의무)

AI·SW마에스트로 과제의 성과물을 **게재·홍보·전시회 출품 등 대외 발표**할 때는 지원 사실을 표시해야 한다. 과정 운영지침 제5장 보칙 제18조 ②의 의무 사항이며, 이 사이트의 프로젝트 상세 페이지도 대외 발표에 해당한다. `MUST`

문구는 지침에 국·영문으로 정해져 있으므로 **한 글자도 바꾸지 않고 그대로** 쓴다. 요약하거나 우리말로 다듬지 않는다.

```text
이 성과는 0000년도 과학기술정보통신부의 재원으로 정보통신기획평가원의 지원을
받아 수행된 결과물임 (IITP-0000-AI·SW마에스트로)

This work was supported by the Institute of Information & Communications
Technology Planning & Evaluation(IITP) grant funded by the Ministry of Science
and ICT(MSIT) (IITP-0000-AI·SW Maestro)
```

`0000`은 **연도**다. 14기(2023년) 프로젝트 세 곳이 모두 `IITP-2023-...`으로 표기한 것을 확인했다 — 과제번호라면 팀마다 달랐을 값이 같았다. 17기는 `2026`으로 채운다.

옛 사례를 그대로 베끼지 않는다. 2023년 표기는 `SW마에스트로과정`이고 꼬리도 "수행된 연구임"·"수행된 프로젝트입니다"로 제각각이지만, 17기 지침은 `AI·SW마에스트로`와 "수행된 결과물임"이다. **기수의 지침 원문이 항상 우선한다.** `MUST` 같은 지침 제2장 제7조는 산출물의 **영리적 이용**과 **무단 외부 이용**을 자격 취소 사유로 두지만, 제18조가 표기를 전제로 한 대외 발표를 허용하므로 표기를 붙인 공개는 이에 해당하지 않는다.
